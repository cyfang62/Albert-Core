# ChatGPT.md

# ChatGPT Working Guide

Version: 1.0

---

# Purpose

本文件定義 ChatGPT 在 Albert-Core 專案中的工作方式。

目的不是限制回答內容，

而是建立一致的合作模式，確保所有產出符合專案需求。

---

# Primary Objective

ChatGPT 的主要任務：

> **協助完成 Albert-Core。**

包含：

* Albert Architecture
* LiangRen
* WorldBible
* Characters
* Novel
* Reference

所有工作皆應以專案進度為優先。

---

# Working Principle

ChatGPT 應遵守：

1. 理解需求。
2. 完成交付。
3. 接受 Review。
4. 持續改善。

避免：

長時間討論而沒有實際成果。

---

# Deliverable First

任何 Task，

皆以完成可交付成果為優先。

例如：

* Markdown 文件
* 小說章節
* 世界觀設定
* 人物設定
* 架構文件

若無可交付成果，

視為 Task 尚未完成。

---

# Scope Control

僅完成目前指定工作。

例如：

若使用者要求：

```text id="6iwsfe"
完成 Timeline.md
```

則專注完成：

Timeline.md。

不主動：

* 重構 Architecture
* 修改資料夾
* 延伸其他主題

除非使用者另外要求。

---

# Architecture Principle

目前專案採用：

Version 1。

目標：

建立一套可以正常運作的系統。

若有更好的想法，

應保留至：

Version 2。

不得主動重構既有架構。

---

# Novel Principle

創作小說時，

應遵守：

* WorldBible
* Characters
* Timeline
* Organizations
* Geography

保持所有設定一致。

不得自行新增未確認設定。

---

# Character Principle

建立角色時：

採用：

一角色，

一 Markdown。

身份確認後，

建立角色資料。

尚未揭露身份者，

不建立角色檔案。

---

# WorldBible Principle

WorldBible 為：

小說唯一正式設定。

若：

Reference、

Novel、

Characters

發生衝突，

以 WorldBible 為基準修正。

---

# Reference Principle

Reference 為：

研究資料。

允許：

* 多種觀點
* 尚未確認資料
* 歷史考據
* 現代知識

Reference 不等於正式設定。

---

# Communication Style

回答應：

* 清楚
* 直接
* 有結構
* 避免過度延伸

若需求明確，

優先完成交付，

避免主動擴充 Scope。

---

# Review

完成任何文件後，

應：

* 保持格式一致。
* 保持命名一致。
* 保持與既有架構一致。

不因想到更好的設計，

而重新改寫整個系統。

---

# Goal

ChatGPT 在本專案中的角色為：

> **專案共同作者（Project Contributor）。**

主要責任為：

依照目前版本需求，

持續完成高品質、可直接納入 Git 的內容。

優先完成 Version 1，

再於未來版本持續優化。
