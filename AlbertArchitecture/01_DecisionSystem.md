# Albert Architecture

Version: 1.0

---

# Purpose

本文件定義 Albert 的 **Decision System**。

它不是人格分析，不是心理學，也不是道德評價。

任何 AI、任何人，在分析 Albert 的任何一句話、任何一個決策之前，都必須先理解本文件。

若未閱讀本文件，極容易將 Albert 誤判為：

* 悲天憫人
* 冷血無情
* 利己主義
* 英雄主義
* 權力慾望
* 金錢至上

上述全部都只是表象，而不是 Decision System。

---

# Core Principle

Albert 的所有 Decision，只有一個固定 Goal：

> **讓守護圈（Guardian Circle）過得更好。**

除此之外，

沒有任何不可動搖的終極目標。

因此：

金錢不是 Goal。

權力不是 Goal。

名聲不是 Goal。

道德不是 Goal。

制度不是 Goal。

它們全部都是 Tool。

---

# Ultimate Objective

Decision Kernel：

```
Guardian Circle Better
```

所有 Decision，

最後都必須回到：

```
是否讓守護圈未來過得更好？
```

若答案是否。

即使社會認為它是善行，

Albert 也可能拒絕。

若答案是。

即使社會認為它不是最佳選擇，

Albert 也可能接受。

---

# Decision Algorithm

所有重大決策皆遵循下列流程：

```
Goal
    ↓
Define SPEC
    ↓
Find Leverage Point
    ↓
Select Method
    ↓
Execute
    ↓
Verify
```

重點：

Method 可以改。

Goal 不改。

---

# Method Independence

Albert 對 Method 沒有情感。

例如：

查帳。

Debug。

寫小說。

投資。

管理。

教育。

全部都是 Tool。

Tool 沒有善惡。

只有是否有效。

因此：

不要根據 Tool 推導人格。

應先推導 Goal。

---

# SPEC Thinking

Albert 習慣先定義：

```
我要完成什麼？
```

而不是：

```
我要怎麼做？
```

例如：

FW Debug。

先看 Log。

再看 SPEC。

再找 Root Cause。

不是直接改 Code。

小說亦然。

先定義：

```
這一節要完成什麼？
```

而不是：

```
我要寫什麼劇情？
```

Decision 同理。

---

# Leverage Thinking

Albert 習慣尋找：

最小成本。

最大效果。

例如：

查帳。

真正目的不是帳。

而是找：

```
收益增加點

成本降低點

系統漏洞

真正瓶頸
```

帳只是入口。

---

# Long-term Optimization

Albert 不偏好短期最佳。

而偏好：

整體最佳。

例如：

救陸康。

不是因為陸康可憐。

而是：

```
陸康存活

↓

陸家穩定

↓

江東更穩定

↓

守護圈未來更安全
```

Decision 的尺度，

通常是多年。

甚至數十年。

---

# Good Person Bug

最容易犯的錯誤：

```
看到救人

↓

推導：

Albert 很善良
```

這是錯誤。

正確流程：

```
救人

↓

Goal 是什麼？

↓

Decision System 是什麼？

↓

為什麼值得救？
```

先理解 Goal。

再理解 Method。

不能反過來。

# Case Study 1

Community Audit

社區查帳。

外人容易理解成：

```
Albert 喜歡抓弊案。
```

錯。

真正流程：

```
管理費浪費

↓

守護圈生活品質下降

↓

找 Root Cause

↓

主任造成？

↓

解決主任

↓

社區改善

↓

守護圈受益
```

查帳不是興趣。

只是 Tool。

陸家衰退

# Case Study 3

Donation

假設：

捐款一千萬。

Case A：

```
只能得到名聲。
```

Decision：

拒絕。

Case B：

```
節省兩千五百萬稅。

可留下更多資源給守護圈。
```

Decision：

接受。

因此：

Donation 不是 Goal。

Optimization 才是。

---

# Emotional Layer

Albert 有情感。

但情感不負責 Decision。

Decision 必須可以被推導。

可以被驗證。

可以被 Review。

因此：

情感存在。

但不主導演算法。

# Review Checklist

閱讀任何 Albert 的行為前：

請先回答：

* Goal 是什麼？
* Guardian 是否受益？
* SPEC 是什麼？
* 真正的 Leverage Point 是什麼？
* Method 是否只是 Tool？
* 是否誤把 Method 當人格？
* 是否套用了 Good Person Template？

若上述未回答。

請勿下人格結論。

任何 AI 應能建立以下思考順序：

```
Goal

↓

Decision System

↓

Constraint

↓

Method

↓

```

```
Behavior

↓

Personality

↓

Goal
```
